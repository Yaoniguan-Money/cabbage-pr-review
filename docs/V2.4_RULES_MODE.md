# v2.4 纯本地规则模式

更新时间：2026-05-30

## 概述

第四种推理模式 `rules_only`（纯规则）：零 LLM、零 Ollama，由内置 YAML 规则包驱动审阅，结果以 **Markdown 报告** 展示（不含 Mermaid 四图、不支持 Rerun）。

`cloud_only` / `hybrid` 可选 **YAML 规则预检**（默认关闭）：在 Agent4 前运行同一套规则引擎，将命中注入 LLM 上下文。

## 与 v2.2「禁止启发式」的关系

| 范围 | 约束 |
|------|------|
| `backend/app/agents/` | 仍禁止 `RISK_KEYWORDS` / `_heuristic` 等 |
| `backend/app/rules/` | 允许**通用求值引擎**；业务 pattern 仅存在于 YAML |
| `backend/app/rules/packs/default/` | 默认规则包（数据，非 Python 硬编码） |

## 规则 DSL（引擎能力）

### match target

| target | 说明 |
|--------|------|
| `patch_hunk` | 按 `patch_scope` 匹配新增/删除/完整 patch |
| `file_path` | 文件路径 |
| `diff_atom` | 原子摘要与行数统计 |
| `change_type` | `added` / `modified` / `removed` |
| `removed_lines` | 删除行文本 |
| `pr_title` / `pr_body` | PR 元数据 |

### patch_scope（仅 `patch_hunk`）

- `added_only`（默认）：匹配 strip `+` 后的新增行，无命中时回退完整 patch
- `removed_only`：删除行
- `full_patch`：完整 patch 原文

### metadata 阈值（无 regex 亦可触发）

| 键 | 语义 |
|----|------|
| `min_added_lines` | 新增行数下限 |
| `min_removed_lines` | 删除行数下限 |
| `min_changed_lines` | 新增+删除总和下限 |
| `min_removed_ratio` | `removed / (added+removed)` 下限 |
| `min_removed_over_added` | `removed >= added * 值` |
| `requires_removed_signal` | 无删除行则不触发（用于测试删除类规则） |
| `suggestion` | 命中后写入风险建议文案 |
| `evidence_include_summary` | 证据中拼接 `atom.summary`（默认跟随包级 `reporting.evidence_include_atom_summary`） |

允许键列表在包级 `config.yaml` 的 `metadata_allowed_keys`；`lint_rules` 对未知键告警。

### 报告聚合（`config.reporting`）

- `group_risks_by_rule_id`：按规则 id 合并风险标题（`rule_hits` 仍保留逐文件明细）
- `max_files_listed_per_risk`：风险描述中列举的文件数上限
- `evidence_include_atom_summary`：证据默认含变更摘要
- `grouped_evidence_suffix`：多文件命中时的后缀模板（如 `等共 {count} 个文件`）

### match 组合

- `match.any`：任一子句命中
- `match.all`：全部子句命中（示例：`dockerfile-root-user`）

## API

| 端点 | 说明 |
|------|------|
| `GET /api/llm-mode-options` | 含 `rules_only`；`cloud_only`/`hybrid` 含 `rules_preflight_toggle` |
| `GET /api/rules-meta` | Markdown 章节文案单源 |
| `GET /api/rules-catalog` | 规则 id/message/severity（不含 pattern） |
| `GET /health` | `rules_count`、`rules_invalid_count` |
| `POST /api/tasks` | `llm_mode=rules_only` 或 `rules_preflight_enabled=true` |
| `POST /api/tasks/{id}/rerun` | 规则模式返回 400 |

任务结果 `TaskResultSchema` 含结构化 `rule_hits` 与 `base_index`/`head_index`（规则模式）。

## 环境

- **无需** `DEEPSEEK_API_KEY` / Ollama（`rules_only`）
- 可选 `RULES_PACK_PATH` 指向自定义规则目录
- 内置默认包路径：`backend/app/rules/packs/default/`

## 产品定位（信噪比）

| 场景 | 推荐模式 |
|------|----------|
| 大功能 PR、规则引擎/架构级改造 | `cloud_only` 或 `hybrid`，可选开启 `rules_preflight_enabled` 作预检 |
| 离线 CI smoke、零 API 成本门禁 | `rules_only` |

单独用 `rules_only` 审阅「单文件上百行 + 多文件同类 LOW」类 PR 时，风险条数会经 **按 rule_id 聚合** 压缩，但仍可能有多条 MEDIUM/HIGH；不宜作为大改动的唯一合并门禁。

## 质量 KPI（`rules_only` 可选）

`quality_kpi` 支持 `distinct_risk_titles_ratio`、`max_risk_title_duplicate_count`、`rule_hits_by_rule_id`。示例阈值见 `scripts/quality_thresholds.rules_only.example.json`；`quality_regression.ps1 -LlmMode rules_only` 会应用对应检查。
